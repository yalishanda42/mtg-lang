# Bulgarian labels and pre-1945 (Ivanchev) spelling — design

Date: 2026-11-25. Status: draft for approval (builder-checked).

## 1. Intent

Step 3 of the multi-language plan (after the semantic AST): show cards in Bulgarian written in the pre-1945
orthography (Ivanchevski pravopis: final ъ, ѣ, ѫ, сѫ …), with an old-Bulgarian literary feel "like reading an
Иван Вазов book". There is no Bulgarian text in the project yet, so this step has two parts, done in order:

- **A. An offline spelling converter** (modern Bulgarian → Ivanchev spelling), usable on any text now and on the
  Bulgarian renderer's output later.
- **B. Bulgarian labels for the whole vocabulary** — every glossary symbol, every name (card names included,
  user's choice), every named effect — in modern spelling (`bg`) plus the Ivanchev spelling (`bg-ivanchev`)
  generated by A and reviewed.

Full Bulgarian card *text* (sentences) is the later renderer project and out of scope here.

## 2. Goals

1. `mtglang ortho "текст"` (and stdin) converts modern Bulgarian to Ivanchev spelling, fully offline.
2. Its accuracy is measured on paired texts (modern ↔ original pre-reform) and reported by a test.
3. Every entry in `glossary/symbols.yaml` (≈200), `names.yaml` (801: 600 card, 157 subtype, 35 flavor,
   9 token) and `named_effects.yaml` (4) gets `bg` and `bg-ivanchev` labels.
4. `mtglang render --lang bg` / `--lang bg-ivanchev` shows the gallery's tooltips, Legend and card names in
   Bulgarian (the renderer already reads `labels[lang]`).
5. One review file for the user: `docs/bg-review.md` — a table `en | bg | bg-ivanchev | note` grouped by kind,
   so the whole translation can be reviewed in one sitting (user's batch-and-review-at-end preference).

## 3. Non-goals

- Bulgarian sentences / card text rendering (next project; it will reuse A on its output).
- Old Church Slavonic, the 1921–23 Omarchevski spelling, or a reverse converter.
- The upstream converter's BERT part-of-speech model and its 21 MB frequency cache (see §5).

## 4. Anti-goals

- **Network at conversion time.** No calls to pravopis.osvedomitel.bg or any service; everything is vendored.
- **Modern bureaucratic Bulgarian.** Labels that read like a software manual ("Добави мана", "Атакуващо
  създание") miss the brief; the register is Vazov-era literary.
- **Untraceable old spellings.** Every `bg-ivanchev` label is either the converter's output or a recorded manual
  override — never a silent hand edit of converter output without a reason.

## 5. Part A — the converter

**Source.** Port the logic of `Peshowe/converter-web-app` (`converter/converter.py`, `process_vocabs.py`; MIT,
© 2021 Petar Nedelev) — the engine behind pravopis.osvedomitel.bg — to dependency-free Python in
`mtglang/ortho/`. No pandas, nltk or keras: a small regex tokenizer replaces nltk.

**Rules ported:** final ъ after consonants (with ь for soft-ending nouns, във/със, abbreviations), ѫ from root
lists (сѫ, пѫть …), ѣ from root lists with exclusions, double-ѣ roots, ѣ-prefixes (прѣ-, двѣ-), past-tense
endings (-ѣше, -ѣха), the `-те` → `-тѣ` plural article, feminine soft endings, special spellings
(праздникъ, сърдце, възстанъ …), case preservation.

**Data vendored** (downloaded once from upstream GitHub, pinned to the commit recorded in the provenance
README — my call; network only at vendoring time, never at conversion time) in `mtglang/ortho/data/` with the upstream LICENSE and a provenance README: yatRoots,
yatExclusions, usRoots, usExclusions, nonYatPrefixRoots, abbreviations, masculine/feminine soft endings,
nouns_in_te, verbs-te, verbs_only_homonyms (≈3.3 MB total; verbs-te is the large one), plus every upstream
paired test text (`text*.txt` / `conv*.txt`) as fixtures. Not vendored: the BERT
weights (for `-те` verb/noun homographs the converter falls back to the non-verb reading, as upstream does
without weights) and `most_freq.txt` (a speed cache only).

**Overrides.** `glossary/ortho_overrides.yaml` has two sections (my call):
- `words: {modern: old}` — word pairs applied before the rules, for converter mistakes and coined MTG words;
- `entries: {<file>:<key>: old}` — a whole `bg-ivanchev` label fixed by hand for one glossary entry (for
  context-dependent spellings like тѣ/те).
Regeneration (`mtglang ortho --glossary`) never overwrites an `entries` label, and refuses to run (listing
the entries) if a `bg-ivanchev` label in the YAML differs from what it would generate without being in
`entries` — so a hand edit can't be lost silently. The converter is a pure function
`to_ivanchev(text, overrides) -> str`.

**Accuracy test.** The upstream repo's paired texts (`text*.txt` modern ↔ `conv*.txt` original) are vendored
as test fixtures; a test reports word accuracy and fails below a threshold set at the first measured value
minus a small margin (so regressions show, without pretending the converter is perfect).

**CLI.** `mtglang ortho [TEXT]` (reads stdin without TEXT) prints the converted text.

## 6. Part B — Bulgarian labels

**Where.** `labels: {en: …, bg: …, bg-ivanchev: …}` on every symbol, name and named effect. `bg` is modern
spelling (input for the future renderer, which inflects modern forms and converts at the end);
`bg-ivanchev` is generated: `to_ivanchev(bg)` + overrides, stored in YAML so the gallery and reviewers see it.
A script `mtglang ortho --glossary` regenerates every `bg-ivanchev` label from `bg` (idempotent).

**Register (the brief).** Literary Bulgarian of the late 19th / early 20th c. (Вазов, Ботев, Яворов,
Елин Пелин): native and Church-Slavonic-flavoured words over modern loanwords, Ottoman-era words where they
fit the scene (юнак, войвода, хайдутин, паша, кадия, сарай), and old forms like "що", "де", "ала" where they
read naturally. Examples of the intended direction (final wording decided while translating):

| en | bg (modern spelling) | bg-ivanchev |
|---|---|---|
| Creature | Създание → *Твар* | Тварь |
| Warrior | Воин | Воинъ |
| Flying | Летеж → *Крилатост* | Крилатость |
| Treasure | Съкровище | Съкровище |
| Ajani's Pridemate | Аджаниев побратим | Аджаниевъ побратимъ |

**Card names** (600) are translated, not transliterated: meaning and wordplay first, Vazov register second;
character names (Ajani, Spock, Garak) are transliterated in the old manner and declined where a name
needs a possessive (Аджаниев). Star Trek proper nouns keep their established Bulgarian transliterations where
one exists (Спок, Кърк), adapted to old spelling.

**Symbol labels** are the Bulgarian Magic vocabulary: keywords and actions get coined terms in the brief's
register; structural/logic labels (if … then, target) stay plain and short. The `definition:` and `oracle:`
fields are not translated (they are notation / English Oracle reference).

**Correctness standard** (my call): period norms, not raw converter output. While translating I check each
generated `bg-ivanchev` label against Ivanchev rules (final ъ/ь incl. soft feminine -ь: тварь, крилатость;
ѣ/ѫ etymology; -тѣ plural article) and record any correction as an override, so the review file shows what was
changed and why.

**Grammatical form** (my call): labels are display/citation forms — nouns in nominative singular (plural only
where the English label is plural), actions in the imperative used on cards ("Изтегли", "Унищожи"),
keywords as nouns or adjectives as they would head a keyword line. Gender, aspect and inflection tables are
not recorded now; they belong to the sentence-renderer project, which will add its own lexicon fields.

**Gallery interface strings** (my call): a small table `glossary/ui_strings.yaml` (`{id: {en, bg,
bg-ivanchev}}`) for the page's fixed words (Legend, Named effects, Glyph, Meaning, Oracle, Save, Revert,
editor hints, symbol class headings); `page.html` reads it for the chosen `--lang`, falling back to English.

**Validation.** `check_glossary` warns (`G-LABEL-BG`, warning, not error) when an entry lacks `bg` or
`bg-ivanchev`, so the corpus stays at 0 errors while the translation is in progress and shows coverage.

**Review file.** `docs/bg-review.md` generated by `mtglang ortho --review` from the glossary: one table per
kind (keywords, actions, types, …, subtypes, card names by set), columns `en | bg | bg-ivanchev | note`
(note = override used, or the translator's remark on a hard name). The user reviews once at the end and tells me
the changes (or edits the YAML directly); I apply them to the YAML / overrides and regenerate the file — no
markdown importer (my call).

## 7. Approaches considered

| | Approach | Trade-off | Verdict |
|---|---|---|---|
| A | Call pravopis.osvedomitel.bg per word/card | Exact upstream output; network per run, rate limits, no control | rejected (anti-goal) |
| B | Hand-write old spellings for every label | Fully controlled; 1000+ judgement calls, no tool for future sentences | rejected |
| **C** | **Port the open-source converter offline + reviewed overrides; store results in YAML** | Deterministic, reusable for sentences later; inherits upstream's known gaps, fixed by overrides | **chosen** |

Order of parts (user's choice): A first, then B.

## 8. Constraints

- Python ≥ 3.12, no new runtime dependencies.
- `symbols.yaml` keeps one `- {…}` line per symbol (glossary editor); `names.yaml` likewise one line per name.
- Glossary editor (`mtglang serve`) edits the `en` label (or `--lang`); it must preserve the other labels.
- Attribution: upstream LICENSE kept next to the vendored data; README credits pravopis.osvedomitel.bg.

## 9. Success criteria

1. `mtglang ortho "Почиват яростни вълни"` → `Почиватъ яростни вълни` offline; accuracy test green.
2. 0 entries without `bg` / `bg-ivanchev` (no `G-LABEL-BG` warnings); `mtglang validate` 0 errors.
3. `mtglang render --lang bg-ivanchev` builds; spot check of the Legend and 10 cards.
4. `docs/bg-review.md` lists every label.
